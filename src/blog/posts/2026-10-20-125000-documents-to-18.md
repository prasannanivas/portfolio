My trading monitor pulls macro context next to technical signals: central-bank rates, plus 2-year and 10-year government bond yields for six countries. Roughly 10,000 daily records per series.

## The first version

The straightforward schema was one document per data point:

```js
{ country: "United States", maturity: "10y", date: "2026-03-20", close: 4.393 }
```

It's easy to write and easy to reason about. It also produced **125,000+ documents**, and every chart on the dashboard needed thousands of them at once.

## How the data is actually read

Nobody ever asks for "the US 10-year yield on one random Tuesday". The dashboard asks for **a whole series** — draw the line, compute the spread, compare two countries.

So the document should be the series:

```js
{
  country: "United States",
  maturity: "10y",
  last_available_date: ISODate("2026-03-20"),
  record_count: 10000,
  data: [ { date: "20/03/2026", open: 4.393, high: 4.393, low: 4.393, close: 4.393 }, /* … */ ]
}
```

Six countries × two maturities = **12 documents** for yields, plus **6** for interest rates.

## What changed

- **125,000+ documents → 18.**
- A chart is now one read, not thousands.
- Incremental updates append to one array instead of inserting new documents.

## When not to do this

Arrays like this stay well under MongoDB's 16 MB document limit for daily data, but this wouldn't work for tick data, or if I regularly queried single points across many series. Schema follows access pattern — not the other way round.
